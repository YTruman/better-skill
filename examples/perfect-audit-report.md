# 满分作业范例：Skill 体检报告（CEO 助理四技能）

> 场景：用本标准给一组对话型 Skill 做系统体检（2026-05 实战案例浓缩）。**模仿其结构神髓与判定纪律，严禁生搬硬套内容。**

**对象**：CEO 助理 4 个技能（想法管理/内容消化/深度研究/任务执行）
**范式判定**：主导范式 = 3·协同共创（Partner）；匹配度 = 中（缺初始协议导致"合伙人感"不足）

## 四层扫描（节选）

| 图层 | 模块 | 判定 | 证据 |
|---|---|---|---|
| 1 | YAML Frontmatter | ✅ | 有 name+description+触发场景；英文 description 触发词不够口语 |
| 1 | 初始对话协议 | ❌ | 四技能触发后直接进入执行，无"我计划分X步，是否开始" |
| 2 | 分阶段退出条件 | ✅ | 每步骤有退出条件 |
| 2 | 质量标准 | ✅ | 每技能有质量标准表 |
| 3 | 黑盒脚本 | N/A | 四技能均为纯文本交互 |
| 4 | references/ 离线库 | ❌ | 无；三套分析方法全部内嵌正文，每次全量加载 |
| 4 | examples/ 满分样本 | ❌ | 有 templates 无 examples，AI 知格式不知"好"长什么样 |

## 红线扫描

- P2-8 无反馈一股脑生成：⚠️ 深度研究/任务执行存在跳过确认直接执行路径

## 评级

P0 缺失 1（初始对话协议）/ P1 薄弱 2（references 外置、examples 样本）/ 红线违例 0 硬伤

## 处方建议（按优先级）

1. [P0] deep-research、task-execution 增加初始对话协议（防方向跑偏，工作量小）
2. [P1] 全部 4 个加 examples/ 满分样本（最快提升 ZSAR 的一招）
3. [P1] deep-research 三套分析方法外置 references/，主文件只留路由句
4. [P2] task-execution 补任务路由决策树；YAML description 加口语触发词

## 辩证裁量示范（本范例的核心神髓）

发现 6"语言风格是描述性中文而非祈使句"——**判定：不改动**。理由：祈使句要求针对技术工具型 Skill；对话型角色 Skill 用描述性语言是设计意图，不是缺陷。体检不是机械套表，是拿标准做工程判断。
