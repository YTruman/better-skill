# 四层模块检查表与 21 条红线（体检 rubric）

> B 模式（体检）与 C 模式（处方）必读。逐层扫描 → 逐条红线扫描 → 按末尾模板出报告。判定只有三态：✅ 通过 / ⚠️ 部分 / ❌ 缺失；不许沉默，"不适用"也要写明理由。

## 四层架构依赖表（总览）

| 图层 | 喻体 | 解决什么 | 依赖 |
|---|---|---|---|
| 1 身份与加载 | 感官/入口 | 何时触发、协作授意 | 无（系统原生） |
| 2 逻辑与智能 | 大脑/中枢 | 如何思考、确定调性 | 依赖层1的上下文 |
| 3 执行与工具 | 手脚/末梢 | 物理产出、确定性 | 依赖层2的策略 |
| 4 资源与支撑 | 基座/骨血 | 知识储备、规范范本 | 横向支撑 1/2/3 |

## 图层一：身份与加载（Identity & Trigger）

| 模块 | 优先级 | 要求 | 一句话判据 |
|---|---|---|---|
| YAML Frontmatter | **P0** | description = 身份 + 三个触发场景 + 独家资源 + 产出属性；≤100 词；"何时用"全在 description，不在正文 | 换 10 种说法提需求，能否被点将 |
| 初始对话协议 | **P0** | 多步任务第一步必须停顿确认："我计划分 X 步，预期产出 Y，是否开始？" | 拿到一句话会不会直接狂奔 |
| 决策树 | P1 | 多分支输入（本地文件 vs URL、类型分叉）必须有 if-then 路径图 | 模糊输入时 AI 知不知道走哪条路 |

## 图层二：逻辑与智能（Logic & Brain）

| 模块 | 优先级 | 要求 | 一句话判据 |
|---|---|---|---|
| 核心执行原则 | **P0** | 潜意识护栏；强力谓词定调性（Pristine / Meticulous） | 有没有"AI 塑料感"的口子 |
| 分阶段工作流 | P1 | 每个 Phase 有明确 Exit Criteria；禁止 Phase 1 就写正式产出 | 长任务会不会注意力溃散 |
| 质量标准与挑刺审计 | P1 | 交付前强制自检："列出 3 个可能缺陷，至少修正 1 个" | 交作业前有没有自我博弈 |
| 哲学驱动层 | P2 | 审美类项目先出宣言（~500字），实现必须 100% 呼应 | 作品有没有灵魂 |

## 图层三：执行与工具（Execution & Tools）

| 模块 | 优先级 | 要求 | 一句话判据 |
|---|---|---|---|
| 黑盒脚本封装 | **P0** | 非文本操作（图像/二进制/网络/旋转合并）必须锁死在 scripts/；AI 只读 --help 不读源码 | 易翻车逻辑是否裸奔在提示词里 |
| 外科手术式编辑 | P1 | 长文档修改只许 str_replace 级补丁，严禁全量重印 | 会不会 Token 熔断 |
| 侦察-响应 | P1 | 动态环境先截图/读 DOM/探测状态，所见贴入思考后再动 | 有没有盲猜选择器 |

## 图层四：资源与支撑（Resource & Assets）

| 模块 | 优先级 | 要求 | 一句话判据 |
|---|---|---|---|
| references/ 离线库 | P1 | 巨量规则/API 规格/黑名单外置；>10k 字文件配 grep 检索模式 | 主文件是否清爽（<500 行） |
| examples/ 满分样本 | P1 | "满分作业"实体样本，搬运结构而非内容 | AI 知不知道"好"长什么样 |
| 自动化评估 | P2 | QA 题集/validate 脚本，出厂前可回归 | 是不是"我觉得好"式交付 |

## ✅ To-Do 十一条必修课

| 优先级 | 动作 | 核心逻辑 |
|---|---|---|
| P0-1 | YAML 描述 SEO 强化 | 决定被点将的概率；触发词 + 场景 + 资源 + 产出 |
| P0-2 | 外科手术式编辑指令 | 保上下文的命根子；只传 diff 补丁 |
| P0-3 | 初始对话协议 | 心理契约；先对齐再动手 |
| P1-4 | 引用库离线化（500行律） | 主文件只留流程，知识进 references/ |
| P1-5 | 分阶段退出条件 | 每关有哨兵，过关有硬标志 |
| P1-6 | 侦察优先 | 没看到的 = 不存在；先截图/读文件再行动 |
| P2-7 | 黑盒执行协议 | 告诉用法即可，严禁读源码浪费上下文 |
| P2-8 | Few-shot 审美锚点 | examples/ 放样板房，设定质量上限 |
| P2-9 | 自动化校验闭环 | 交付前跑 validate，按报错递归修正 |
| P2-10 | Grep 精准提取 | 万字 reference 配检索词典，禁止全读 |
| P3-11 | 递归"读者"验证 | 模拟无记忆新实例读产出，有疑惑即回滚 |

## ❌ Not-To-Do 十条红线

| 优先级 | 禁忌 | 后果 |
|---|---|---|
| P0-1 | 严禁创建 README/INSTALL/CHANGELOG 等人读文档（豁免：作为独立开源仓发布时，门面文件不受此限，技能安装态仍以 SKILL.md 为唯一入口） | 无效噪音，机器库不需要客套 |
| P0-2 | 严禁对话式废话/独白 | Token 浪费；正文只能有规则、指令、代码 |
| P0-3 | 严禁猜测环境状态（路径/ID/页面） | 鲁棒性杀手；没侦察过 = 不存在 |
| P1-4 | 严禁模糊形容词（Beautiful/Good/Smart） | 审美偏差；改用具体参数或对标 |
| P1-5 | 严禁硬编码巨量数据在主文件 | 主文件膨胀；数据走 references/assets |
| P1-6 | 严禁单次全量重印长文 | 回声灾难，Token 熔断 |
| P2-7 | 严禁非标字符/美化过度 | 技术环境兼容性 |
| P2-8 | 严禁无反馈一股脑生成 | 方向性毁灭；关键决策点设人类中断器 |
| P2-9 | 严禁擅改核心脚本 | 确定性丧失；脚本标记 Read-only |
| P3-10 | 严禁单人独舞式生成 | 盲区风险；引入第二人称审计博弈 |
