# 设计原则与底层原理

> 供 A 模式（造前咨询）定调、以及任何需要向用户讲清"为什么"的场景。来源：官方 300+ 技能审计 + skill-creator 官方文档对撞萃取。

## 三大底层哲学

### 原则一：节制的美学（Concise is Key / Token Economy）

- 上下文窗口是公共资源：Skill 与系统提示、对话历史、其他技能元数据共享窗口。
- AI 已经很聪明：只添加它尚不具备的上下文。拷问每一段文字："这段话值得它的 Token 成本吗？"
- 拒绝系统冗余：不解释"什么是 PPT"，只写"在这个具体场景下，这东西应该长什么样"。
- 无情感输出：全篇祈使句。删掉"我认为最好是……"，直接写"Create the file..."。
- 相比冗长的解释，更偏爱简洁的示例（Show, don't tell）。

### 原则二：自由度匹配（Degrees of Freedom）

评估任务是"悬崖上的窄桥"（高度易错，强行护栏）还是"开阔的平原"（创意发散，自由探索）：

| 自由度 | 手段 | 适用 |
|---|---|---|
| 高 | 文字引导、灵感锚点 | 文案、哲学、头脑风暴 |
| 中 | 模板 + 占位符，`str_replace` 定点填充 | 报告、表格、格式产出 |
| 极低 | 黑盒脚本工具链（scripts/ 带参数） | 精确旋转 PDF、打包编译、二进制操作 |

错配即事故：把悬崖任务给了高自由度 = 鲁棒性杀手；把平原任务锁死 = 浪费智能。

### 原则三：前置认知与解耦思维（Cognitive Grounding）

- 作者诅咒（Curse of Knowledge）：写下 Skill 的人默认读者知道背景——通用 AI 一无所知。
- 重度协作的 Skill 严禁拿到一两句话就干活：强制先经历"信息倾倒与背景收集"阶段（初始对话协议）。
- 解耦：每次都要读的知识放 SKILL.md；按需才读的放 references/；不需要读只执行的放 scripts/。

## 渐进式披露的三级加载（物理机制）

1. **L1 元数据**（name + description）：常驻上下文，约 100 词内。决定被点将的概率。
2. **L2 正文**（SKILL.md）：触发后加载。< 5000 字、建议 < 500 行。
3. **L3 资源**（references/ scripts/ assets/）：按需加载或根本不进上下文（脚本直接执行）。

## 硬物理限值（官方对撞萃取，100/5000/Grep 三律）

- description ≤ 100 词：身份定义 + 三个触发场景短语 + 独家资源 + 产出物属性。
- SKILL.md 正文 < 5000 字 / 500 行：超限即剥离到 references/ 并在主文件留"何时读它"的索引。
- references/ 单文件 > 10k 字时：必须在 SKILL.md 里提供 grep 检索模式（关键词 → 定位），禁止全量通读。

## 反 AI 塑料感（Anti-Slop，审美层原理）

- Skill 的最高境界不是 SOP，是**概率裁剪**：通过禁止平庸选项，把 AI 推向高水准输出的边缘。
- 顶级 Skill 在给 AI 注入性格：挑剔、偏执、有立场（见 templates.md 的禁用词表）。
- 审美价值观要写成可判定的规则（具体参数 12pt / 对标 "Like Stripe API docs"），不写 "Beautiful"。
