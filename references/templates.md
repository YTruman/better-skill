# 全套文档模板与生成 SOP

> A 模式（蓝图产出）与 C 模式（处方补丁）产出时加载。收编自本标准两套前身内部工具（创作专家数据包、多轮协作生成器），与官方 skill-creator 模板对齐。

## 一、YAML 标准块（P0）

```yaml
---
name: <kebab-case，动词词组，如 research-analyzer>
description: <身份定义> + <三个触发场景短语> + <独家资源列表> + <产出物属性>。≤100 词，"何时用"全在这，不放正文。
---
```

例：`深度研究报告专家。在需要进行全网信息检索、学术论文摘要提取或构建行业竞争格局图谱时使用。包含独家 search_scripts。产出物具备 McKinsey 风格的顶级排版。`

**2026-08 官方新口径（pushy 原则）**：模型普遍"欠触发"——description 要写得主动一点（如"凡用户提到 X / Y / Z 都要用本技能，即使没点名"），宁长勿漏；本体系"超 100 词线不改"的本地裁量与此官方转向吻合。触发效果用 `eval-loop.md` §2 的方法实测验证，不拍脑袋。

## 二、初始对话协议模板（P0）

> 我已识别到您的 [需求名称] 意图。我计划按照以下架构进行：1. [Phase 1]；2. [Phase 2]……产出物将遵循 [调性标准]。是否现在开始？

## 三、Anti-Slop 词库（反塑料感）

- **强制禁用词**：Smart / Seamless / Empower / Comprehensive / Innovate / Beautiful / Good。
- **替换策略**：具体参数（"Latency < 200ms"、"12pt"）或具体对标（"Like Stripe API docs"、"Like ex01"）。
- **美学宣言关键词库**：视觉类 Pristine / Meticulous / Minimalist / Hierarchical；思维类 Risk-first / First-principles / Logical pre-filling。

## 四、SKILL.md 主控模板

```markdown
---
<YAML 标准块>
---

# <技能显示名>

## 核心目标与审美宣言
<强力谓词定义的专业调性；审美类项目此处为 500 字宣言，实现必须 100% 呼应>

## 触发与决策路由
<何时启动 + if-then 决策树（多分支时）>

## 核心工作流
### Phase 1: <名称>
- 执行指令：<祈使句>
- 退出条件：<可判定的硬标志>
<更多 Phase…>

## 执行约束与红线
- <红线规则>

## 资源引用
- [何时读哪个 reference](references/xxx.md)；>10k 字文件附 grep 关键词
```

## 五、目录样板

```text
skill-name/
├── SKILL.md          # 意图路由、性格锚点（<500 行）
├── references/       # 静态知识、API 文档、规则集（按需加载）
├── scripts/          # 黑盒执行/验证脚本（只读用法，配 --help）
├── examples/         # 满分作业范本（搬运结构，非内容）
└── assets/           # 模板、字体、图标（不进上下文）
```

禁止创建：README / INSTALLATION_GUIDE / QUICK_REFERENCE / CHANGELOG 等人读文档（豁免：独立开源仓的门面文件不受此限，见 checklist P0-1）。

## 六、references/ 与 examples/ 模板

references 模板：标题 → 使用说明（何时读）→ 目录（>100 行时）→ 分章内容。
examples 模板：场景描述 → 满分输出展示 → 尾注"仅供模仿结构神髓，严禁生搬硬套内容"。

## 七、六阶段生成 SOP（A 模式全流程）

| 阶段 | 动作 | 退出条件 |
|---|---|---|
| A 需求采集 | 问 5-8 个最小必要问题（领域/触发语义/产出形态/环境约束/脆弱点/质量门槛/复现需求/品牌 token） | 范围 + 硬门槛 + 工具清单清晰 |
| B 范式选择 | 按 paradigms.md 定 1-2 个主导范式 + 理由 + 固定/可变合约 | 主范式与质量门槛明确 |
| C 目录设计 | 最小而完整的包结构，逐文件角色 | 每个文件的存在理由成立 |
| D 生成主文件 | 按模板四产出 SKILL.md（祈使句、<500 行、seed 快照如涉及随机） | 一版可直接投入使用 |
| E 验证闭环 | 六项自检：触发可测 / Exit Criteria 可判定 / 固定可变清晰 / 黑盒失败路径覆盖 / 可复现 / 指标可采集 | 无阻断性缺陷 |
| F 交付 | 主文件 + 扩展建议；复杂件附 1-2 个参考链接 | 用户验收 |

## 八、处方补丁规范（C 模式专用）

- 一条发现 = 一个最小 diff；修 P0 严禁顺手改无关内容。
- 补丁格式：`[P0-2] <文件>:<行号范围> str_replace <旧> → <新>，理由一句话`。
- 涉及随机性/生成：补丁必须保留 seed 与参数快照约定。
- 补丁后复诊：重扫受影响检查项，输出前后对比。
